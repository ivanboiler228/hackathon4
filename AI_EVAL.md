# Оценка качества AI и контрольная проверка 80%

Документ закрывает пункт ТЗ **7.5**: «На контрольной расшифровке ассистент выделяет
решения и не менее 80% явно сформулированных задач; неверные пункты можно исправить
до сохранения».

Источник требования: `ТЗ_Хакатон_Единая_система_управления_компанией.pdf`,
раздел **7.5 «Критерии приёмки трека 3»**, страница 8.

---

## 1. Как считали

- Модель: `deepseek-chat`, `temperature=0.2`, `max_tokens=1600`.
- Расшифровка перед отправкой маскируется; в модель уходит только текст с тегами.
- Задача = **одно поручение ответственному в одной реплике**. Если в одной реплике
  несколько действий, это одна составная задача.
- Совпадение проверяли по смыслу: ключевые слова в названии + ответственный.
- Ошибочные/лишние пункты можно исправить в UI до сохранения — это разрешено ТЗ.

Команда для повторного замера:

```powershell
python scripts\eval_meeting_tasks.py
```

---

## 2. Результат на трёх контрольных расшифровках

| Расшифровка | Явно сформулированных задач | Извлечено корректно | Recall |
|---|---:|---:|---:|
| `night_shift_week48.txt` | 2 | 2 | 100% |
| `sla_support_review.txt` | 2 | 2 | 100% |
| `mobile_beta_sync.txt` | 1 | 1 | 100% |
| **Итого** | **5** | **5** | **100%** |

Что извлечено:

- «Подготовить график смен» — Игорь, пятница;
- «Сверить остатки бумаги и заказать бумагу с запасом» — Павел, среда;
- «Обновить скрипты по доставке» — Мария, 18 ноября;
- «Согласовать новые сроки с подрядчиком» — Дмитрий, без срока;
- «Подготовить список клиентов для беты» — Мария, до пятницы.

### Консервативный пересчёт

Если дробить составное поручение «сверь остатки и закажи бумагу» на два отдельных
действия, получается 6 ожидаемых задач, а извлечено 5:

```
5 / 6 = 83,3%
```

Это всё равно выше порога **80%**. Поэтому результат устойчив к трактовке
«задача = действие».

## 3. Проверка нерелевантной записи

Проверяли сценарий: тема встречи «Итоги недели», а в записи только бытовой текст
«Я сегодня ел рыбу и смотрел телевизор».

Результат:

```json
{
  "topic_match": false,
  "summary": "В записи нет обсуждения темы «Итоги недели».",
  "decided": [],
  "tasks": [],
  "risks": []
}
```

То есть ассистент не выдумывает решения и задачи, а честно говорит, что темы встречи
в записи нет.

## 4. Контрольные проверки доступа и источников

| Проверка | Ожидание | Результат |
|---|---|---|
| Вопрос «Что грозит пику в неделю 48?» | Ответ по `D-15`, дефицит 14% | ✅ |
| Вопрос про SLA первого ответа | Ответ по `D-07`, 92% при цели 95% | ✅ |
| Игорь (производство) просит `D-12` (финансы) | `403` + запись в аудите | ✅ |
| Запись не по теме встречи | `topic_match=false`, пустые задачи | ✅ |
| 5 явных задач из 3 расшифровок | Не менее 80% | ✅ 100% (5/5) |

Полный список контрольных вопросов и ожидаемых источников — в `README.md`,
раздел «Контрольные вопросы для проверки AI».

## 5. Ограничения

- Выборка маленькая: 3 синтетические расшифровки, 5 поручений.
- Один прогон на модели; LLM вероятностная, результат может немного меняться.
- Жюри может дать свою контрольную расшифровку — на ней нужно повторить замер
  той же командой.
- Если модель недоступна, включается локальный fallback: он не извлекает задачи,
  а показывает первые 700 символов расшифровки.
- 100% на нашем наборе не означает 100% на любых реальных встречах; для пилота
  нужен более широкий набор и ручная оценка.

## 6. Что сказать жюри

> Мы не заявляем 80% «на словах». На трёх контрольных расшифровках ассистент извлёк
> 5 из 5 явно сформулированных поручений — 100%. Даже при консервативном подсчёте,
> где составное поручение делится на два действия, получается 5 из 6 — 83,3%, выше
> порога 80%. Скрипт замера лежит в репозитории, результат воспроизводится командой
> `python scripts\eval_meeting_tasks.py`. Набор синтетический, поэтому на чужой
> расшифровке замер нужно повторить.
