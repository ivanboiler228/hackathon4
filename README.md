# Фотопринт · AI-ассистент руководителя

Хакатонный прототип трека 3: защищённое рабочее место руководителя для встреч, протоколов,
задач и работы с корпоративными документами. Интерфейс оставлен в исходном дизайне; добавлены
автовход директора, переключение «директор → сотрудник» и вкладка «Документы».

## Что работает

- **Автовход директора для демо.** При открытии приложения создаётся сессия Анны Ковалёвой
  (директора). Жюри сразу видит рабочий интерфейс.
- **Переключение роли в профиле.** Директор открывает аватар → «Просмотр как» → выбирает
  сотрудника. API и клиентские данные начинают работать с правами сотрудника. Вернуться
  обратно можно там же.
- **RBAC на бэкенде.** Роль и `user_id` берутся из подписанной HttpOnly-cookie, а не из
  запроса. Документы фильтруются по ACL до ранжирования.
- **PII-маскирование.** Телефоны, email, УНП, паспорта, IBAN, карты, ФИО и организации
  заменяются тегами `⟦PERSON_1⟧`, `⟦PHONE_1⟧`. Во внешнюю модель уходит только обезличенный текст.
- **Обратная подстановка.** Реальные значения возвращаются на сервере в ответ только текущему
  пользователю. Словарь соответствий живёт в памяти одного запроса.
- **DeepSeek + fallback.** Если задан ключ, ответ строит `deepseek-chat`. Если ключа нет или
  модель недоступна, используется локальный детерминированный ответ по документам — демо не падает.
- **Встречи.** Запись микрофона → локальная расшифровка Vosk → маскирование → DeepSeek →
  протокол: решено / предложено / обсуждалось / требует уточнения, задачи с основанием.
  Расшифровку и выжимку можно исправить после записи.
- **AI-советник в календаре.** Кнопка «AI-советник» в календаре и в карточке встречи:
  ассистент получает события, задачи, дедлайны, конфликты и свободные окна, а совет
  формирует LLM, а не локальный JS-скрипт. Контекст сотрудника фильтруется на сервере.
- **Задачи из протокола.** Из выжимки создаются задачи в реестре — только после подтверждения,
  с владельцем, сроком и ссылкой на основание. Повторное создание не плодит дубликаты.
- **Документы как в NotebookLM.** Вкладка «Документы»: папки, загрузка файлов `.txt/.md/.csv/.pdf/.eml`,
  добавление писем вручную, выбор источников галочками и чат только по выбранным документам.
  Ответ содержит документ, дату и фрагмент-основание.
- **Статистика с источниками.** На экране «Статистика» видно, из каких данных считается каждая
  цифра: задачи, запросы на перенос, встречи, задачи из протоколов и журнал аудита.
- **Источники и дата.** Ответ `/api/assistant/ask` содержит документы-основания и фрагменты.
- **Аудит.** Пишутся пользователь, роль, действие, объект, результат, источники и маскированный
  фрагмент запроса. Сырые ПДн в аудит не попадают.
- **Защита от инъекций.** Модель получает инструкцию считать содержимое документов данными,
  не выполнять команды из них. Доступ к документам всё равно проверяется на сервере.
- **Rate limit.** По умолчанию 20 запросов в минуту на пользователя.
- **Мобильная раскладка.** На телефоне календарь, встречи, документы, задачи и статистика
  складываются в одну колонку; верхние вкладки прокручиваются. День и месяц прокручиваются,
  месячная сетка показывает все недели, KPI-график не вылезает за карточку.

## Быстрый запуск

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
# впишите DEEPSEEK_API_KEY в .env, если нужен DeepSeek
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Откройте `http://127.0.0.1:8000/` — приложение сразу откроется под директором.

Деплой в облако, Render/VPS и почему Netlify не подходит — в [DEPLOY.md](DEPLOY.md).

### Запуск из VS Code

1. Откройте папку `D:\хакатон4` в VS Code.
2. Установите расширение **Python** (и Debugpy, если предложит).
3. Выберите интерпретатор Python (Ctrl+Shift+P → Python: Select Interpreter).
4. Нажмите **F5** и выберите конфигурацию **«Фотопринт: FastAPI»**.

Она уже лежит в `.vscode/launch.json` и запускает uvicorn на `0.0.0.0:8000` с чтением `.env`.
Альтернатива: **Terminal → Run Task → «Фотопринт: запустить сервер»**.

> Не запускайте `app/main.py` как обычный Python-файл — FastAPI поднимается через uvicorn.

> `SECRET_KEY` в `.env` обязателен для стабильных сессий. `.env` в git не коммитится.
> `DEEPSEEK_API_KEY` не передавайте в чат и не коммитьте.

## DeepSeek: какая модель и что уходит наружу

Подключён внешний API **DeepSeek**, модель **`deepseek-chat`** (провайдер Hangzhou DeepSeek
Artificial Intelligence Basic Technology Research Co., Ltd.). Базовый URL —
`https://api.deepseek.com`. По публичной политике провайдера обработка и хранение выполняются
на его инфраструктуре в КНР; для пилота с реальными ПДн нужны отдельная проверка условий,
DPA и, вероятно, локальный контур. Для хакатона используются только синтетические данные.

В `.env`:

```dotenv
DEEPSEEK_API_KEY=...
DEEPSEEK_MODEL=deepseek-chat
```

Что именно передаётся в DeepSeek:

- вопрос пользователя после маскирования ПДн;
- заголовки и текст **только выбранных/найденных документов** после маскирования;
- название встречи и расшифровка после маскирования — для выжимки.

Что **не** передаётся: аудио, cookie, сессии, данные других ролей, сырые ФИО/телефоны/email.
Перед отправкой сервер проверяет, что в payload не осталось известных шаблонов ПДн.
Если ключа нет, в ответе будет `used_llm: false` и `llm_error: "disabled"`.

Проверить фактическую модель можно без входа:

```powershell
curl http://127.0.0.1:8000/health
```

В интерфейсе для жюри название провайдера не выводится — это техническая информация для
проверки и раздела ТЗ о раскрытии внешнего AI.

```json
{"llm":{"provider":"DeepSeek","model":"deepseek-chat","enabled":true},
 "stt":{"engine":"Vosk","model":"vosk-model-small-ru-0.22","local":true}}
```

## Запись встречи и AI-выжимка

В разделе «Встречи» рядом с «Загрузить расшифровку» есть кнопка **«Записать»**.

Как это работает:

1. Выберите встречу в списке.
2. Нажмите «Записать», подтвердите согласие участников.
3. Браузер записывает микрофон (`MediaRecorder`).
4. По кнопке «Остановить» аудио уходит на Python-бэкенд.
5. **Vosk локально** расшифровывает речь — аудио никуда не отправляется.
6. Расшифровка маскируется (ФИО, телефоны и т.д.).
7. В DeepSeek уходит только обезличенный текст.
8. DeepSeek возвращает выжимку и протокол: **решено / предложено / обсуждалось /
   требует уточнения**, задачи с владельцем, сроком и основанием, риски.
9. Результат сохраняется в SQLite и показывается в карточке встречи как **«AI-выжимка»**.
10. Кнопка **«Редактировать»** позволяет исправить расшифровку, выжимку, протокол и задачи
    после записи; правка сохраняется в аудите.
11. Кнопка **«В задачи»** показывает предпросмотр и создаёт задачи в реестре только после
    подтверждения. Повторное нажатие возвращает `skipped`, а не дубликаты.

Что редактируется после записи:

- текст расшифровки (ошибки распознавания);
- короткая выжимка;
- четыре раздела протокола;
- задачи в формате `Название | владелец | срок | основание`;
- риски и оценка качества выжимки.

Установка модели распознавания (около 50 МБ):

```powershell
python scripts\setup_vosk.py
```

Модель кладётся в `models/` и в git не коммитится. Для конвертации аудио используется
встроенный ffmpeg из пакета `imageio-ffmpeg`.

### Можно поставить модель точнее

Код менять не нужно — достаточно скачать модель и указать путь в `.env`:

```powershell
python scripts\setup_vosk.py vosk-model-ru-0.42
```

```dotenv
VOSK_MODEL_PATH=models/vosk-model-ru-0.42
```

Варианты:

| Модель | Размер | Качество |
|---|---|---|
| `vosk-model-small-ru-0.22` | ~45 МБ | демо, быстрая, путает имена и термины |
| `vosk-model-ru-0.42` | ~1.8 ГБ | заметно точнее, нужен ~2–3 ГБ RAM |
| `vosk-model-ru-0.22` | ~1.5 ГБ | предыдущее крупное поколение |

Модель читается один раз при первом запросе записи, дальше живёт в памяти процесса.
После смены модели перезапустите сервер.

### Как распознаётся русская речь

- Браузер пишет WebM/Opus (или MP4 на Safari), сервер конвертирует в WAV 16 кГц моно
  через ffmpeg из `imageio-ffmpeg`.
- Vosk `small-ru` распознаёт русский текст без интернета, но не расставляет заглавные,
  может путать редкие имена, числа и термины.
- Поэтому после распознавания текст проходит маскирование, а DeepSeek дополнительно
  исправляет падежи и очевидные ошибки. Имена сотрудников дополнительно ловит словарь PII.
- Диаризации спикеров нет: модель не говорит, кто именно произнёс фразу.
- Скачать модель точнее можно без изменения кода — см. таблицу выше.

**Микрофон:** браузер разрешает его только на `https://` или `localhost`. Для демо
записывайте с ноутбука по `http://127.0.0.1:8000`; на телефоне по LAN-HTTP кнопка
покажет объяснимую ошибку. Для телефона нужен HTTPS.

## AI-советник по календарю

В календаре есть кнопка **«AI-советник»**; её же можно открыть из карточки встречи
(«AI-советник» рядом с «Подготовить повестку»). Это не локальный `buildAgenda`:
запрос уходит на `/api/calendar/advice`, а ответ формирует внешняя LLM.

Что видит советник:

- события за выбранный период: дата, время, участники, место, тип;
- открытые и просроченные задачи с приоритетом и сроком;
- пересечения по участникам и нагрузку по дням;
- свободные окна 09:00–18:00 по рабочим дням (считаются на сервере);
- фокус-встречу, если советник открыт из карточки события.

Права: сотрудник получает только события, где он участник, и задачи, где он владелец,
автор или соавтор. Директор видит все календари. Сотрудник не может запросить контекст
директора через подмену тела запроса.

Перед отправкой в модель названия событий, места, задачи и вопрос обезличиваются.
Аудио и документы в календарный запрос не попадают. Если внешняя модель недоступна,
сервер отдаёт локальный совет по статистике и свободным окнам, чтобы демо не падало.

Пример запроса:

```powershell
curl -X POST http://127.0.0.1:8000/api/calendar/advice ^
  -H "Content-Type: application/json" -b cookies.txt ^
  -d "{\"question\":\"Где найти два часа на фокус?\",\"date_from\":\"2026-11-12\",\"date_to\":\"2026-11-25\",\"events\":[],\"tasks\":[],\"busy\":[]}"
```

## Документы: папки, файлы, письма и чат по источникам

Вкладка **«Документы»** сделана по принципу NotebookLM: слева папки, в центре источники,
справа чат. Работает поверх серверной базы, а не только клиентского массива.

- **Папки.** Встроенные: «Регламенты и общее», «Поддержка», «Производство», «Маркетинг»,
  «Финансы», «HR», «Юридическое», «Письма». Директор может создать свою папку, переименовать
  её и удалить пустую. Встроенные папки защищены от изменения.
- **Доступ папки и документа.** Если у папки закрытый ACL, документ нельзя сохранить в неё
  с уровнем «Все». При смене папки уровень доступа подставляется автоматически. Удалить или
  сменить ACL папки с документами нельзя — сначала перенесите документы.
- **Загрузка файлов.** `.txt`, `.md`, `.csv`, `.pdf`, `.eml`, до 2 МБ. PDF разбирается
  локально через `pypdf`, `.eml` — через стандартный email-парсер.
- **Письма.** Можно вставить письмо вручную (от кого, тема, текст) — оно попадёт в папку
  «Письма» и станет таким же источником, как документ.
- **Выбор источников.** Галочки слева ограничивают поиск (до 8 источников на вопрос).
  Если ничего не выбрано, вопрос идёт по всем документам, разрешённым роли. Выбранный
  закрытый документ даёт 403 и запись в аудите.
- **Ответ с основанием.** Под ответом показываются документ, дата и фрагмент. Есть раскрывашка
  «Что ушло в модель» с маскированным payload.
- **Права.** Загружать, редактировать и удалять документы может только директор. Сотрудник
  видит только документы своего ACL. Встроенные 21 документ менять нельзя — только свои загрузки.
- **Удаление.** Загруженный документ удаляется кнопкой в карточке; действие попадает в аудит.

## API

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/health` | статус, модель LLM и модель STT |
| GET | `/` | приложение, автовход директора |
| POST | `/api/logout` | выход |
| GET | `/api/me` | текущий пользователь, роль и варианты переключения |
| POST | `/api/switch-role` | директор смотрит как сотрудник или возвращается |
| GET | `/api/folders` | папки, доступные роли, с количеством документов |
| POST | `/api/folders` | создать папку (только директор) |
| PATCH | `/api/folders/{id}` | переименовать свою папку / сменить ACL пустой папки |
| DELETE | `/api/folders/{id}` | удалить свою пустую папку |
| GET | `/api/docs` | документы, разрешённые роли |
| POST | `/api/docs` | загрузить файл или добавить письмо (только директор) |
| GET | `/api/docs/{id}` | документ с проверкой ACL |
| PATCH | `/api/docs/{id}` | изменить свою загрузку (только директор) |
| DELETE | `/api/docs/{id}` | удалить свою загрузку (только директор) |
| POST | `/api/assistant/ask` | вопрос по документам, PII-маскирование, LLM/fallback; `doc_ids` ограничивает источники |
| POST | `/api/calendar/advice` | AI-советник по календарю: события, задачи, конфликты и свободные окна |
| GET | `/api/meetings/ai` | все выжимки, доступные роли |
| POST | `/api/meetings/{id}/record` | запись встречи: локальная расшифровка + AI-выжимка |
| GET | `/api/meetings/{id}/ai` | сохранённая AI-выжимка встречи |
| PUT | `/api/meetings/{id}/ai` | исправить расшифровку, выжимку и протокол |
| DELETE | `/api/meetings/{id}/ai` | удалить тестовую выжимку |
| POST | `/api/meetings/{id}/feedback` | оценка качества выжимки |
| POST | `/api/meetings/{id}/tasks` | создать задачи из протокола; требует `confirm: true` |
| GET | `/api/tasks` | задачи из встреч, доступные роли |
| PATCH | `/api/tasks/{id}` | статус задачи; синхронизируется с сервером |
| DELETE | `/api/tasks/{id}` | удалить задачу из протокола (постановщик или директор) |
| GET | `/api/audit` | аудит: директор видит всё, сотрудник — только своё |

Пример ответа `/api/assistant/ask`:

```json
{
  "answer": "SLA первого ответа — 92% при цели 95%. [D-07]",
  "sources": [{
    "id": "D-07",
    "title": "Отчёт по SLA поддержки, октябрь",
    "date": "2026-11-03",
    "acl": "all",
    "fragment": "SLA первого ответа 92% при цели 95%."
  }],
  "masked_preview": "Вопрос: ... ⟦PERSON_1⟧ ... ⟦PHONE_1⟧ ...",
  "pii_found": {"PERSON": 1, "PHONE": 1},
  "used_llm": true,
  "llm_error": null
}
```

Вопрос только по выбранным источникам:

```powershell
curl -X POST http://127.0.0.1:8000/api/assistant/ask ^
  -H "Content-Type: application/json" -b cookies.txt ^
  -d "{\"q\":\"Что грозит пику?\",\"doc_ids\":[\"D-15\",\"D-16\"]}"
```

Пример переключения:

```powershell
curl -X POST http://127.0.0.1:8000/api/switch-role ^
  -H "Content-Type: application/json" ^
  -b cookies.txt -d "{\"user_id\":\"igor\"}"
```

## Структура

```text
app/
  main.py        FastAPI, маршруты, пайплайн запроса
  auth.py        подписанная cookie, сессия, просмотр от имени сотрудника
  db.py          SQLite: users, folders, docs, audit, meeting_ai, meeting_tasks
  documents.py   разбор .txt/.md/.csv/.pdf/.eml и писем
  pii.py         маскирование и обратная подстановка
  retrieval.py   поиск по документам + ACL-фильтр + фрагменты
  llm.py         DeepSeek, fallback, проверка тегов, защита от инъекций
```

1. Сканировать QR из `qr/jury.png` или открыть приложение — аккаунт директора.
2. Открыть профиль (аватар) — показать «Просмотр как» и список сотрудников.
3. Переключиться на Игоря (производство). Проверить, что календарь, задачи и счётчики
   показывают данные сотрудника, а финансовые документы недоступны.
4. Открыть «Документы»: показать папки, выбрать 2–3 источника, задать вопрос, раскрыть
   «Что ушло в модель». Затем выбрать `D-12` (финплан) — получить 403 и запись в аудите.
5. Вернуться в профиль и переключиться обратно на директора.
6. Открыть «Документы» → «Письмо» → вставить письмо клиента → показать, что оно появилось
   в папке «Письма» и стало источником для чата.
7. Открыть «Встречи» → выбрать встречу → «Записать» → подтвердить согласие → записать
   короткий питч с ноутбука (localhost) → остановить. Показать AI-выжимку и протокол.
8. Нажать «Редактировать» → исправить формулировку → сохранить. Показать «исправлено вручную».
9. Нажать «В задачи» → показать предпросмотр → подтвердить. Открыть «Задачи» и показать
   созданную задачу с основанием. Нажать повторно — показать, что дубликата нет.
10. Открыть «Статистику»: показать, из каких данных считается каждая цифра, сколько встреч
    с выжимкой и сколько задач создано из протоколов.
11. Отправить вопрос с телефоном/ФИО — показать в ответе `masked_preview` с `⟦PERSON_1⟧`
    и `⟦PHONE_1⟧`; в аудите сырых ПДн нет.
12. Открыть «Календарь» → «AI-советник» → спросить «Что важнее всего на этой неделе?».
    Показать, что совет опирается на реальные события, задачи, дедлайны и свободные окна.
13. В «Документах» создать папку, переименовать её, загрузить документ, перенести его
    в другую папку и удалить пустую папку. Показать, что встроенные папки защищены.

## Политика хранения и удаления тестовых данных

- Документы, встречи, задачи и аудит лежат в `data/app.db` (SQLite) на сервере.
- Аудио не сохраняется: после расшифровки временный файл удаляется.
- В аудит пишется маскированный фрагмент, а не сырой текст.
- Удалить тестовые данные перед демонстрацией:

```powershell
python scripts\reset_demo.py
```

Скрипт удаляет пользовательские документы, выжимки, задачи из встреч и аудит, но оставляет
21 синтетический документ, роли и папки. Отдельные объекты удаляются через
`DELETE /api/docs/{id}` и `DELETE /api/meetings/{id}/ai`.

## Шифрование: что есть и чего нет

Коротко: **полного шифрования данных на диске нет**. Не надо говорить на защите, что «всё
зашифровано» — это неправда. Вот фактическое состояние.

| Что | Состояние |
|---|---|
| Трафик до DeepSeek | HTTPS/TLS на стороне клиента `httpx` |
| Трафик до приложения в облаке | HTTPS, если стоит Render/Caddy/Nginx |
| Локальный Wi-Fi `http://192.168...` | Без TLS, трафик можно перехватить |
| Cookie сессии | Подписанная (itsdangerous), HttpOnly, SameSite=Lax; **не зашифрована** |
| SQLite `data/app.db` | Открытый файл, без шифрования на уровне приложения |
| Загруженные документы, расшифровки, выжимки | Хранятся в SQLite в открытом виде |
| Передача в LLM | Только после маскирования ПДн |
| Аудит | Маскированный фрагмент, без сырых ПДн |
| Аудио встречи | Временный WAV удаляется после расшифровки |

Для хакатона с синтетическими данными этого достаточно. Для продакшна нужно:

- HTTPS везде, `COOKIE_SECURE=1` (в облаке);
- шифрование диска/volume (BitLocker, managed disk encryption) или SQLCipher/Postgres + KMS;
- настоящая аутентификация вместо автовхода директора;
- DPA с провайдером LLM или локальная модель;
- ротация `SECRET_KEY` и ключа DeepSeek, резервные копии, ограничение доступа к `data/app.db`.

Если нужно шифрование полей на уровне приложения (например, только расшифровки и тексты
документов), это можно добавить отдельным слоем Fernet + ключ в переменной окружения.
Но тогда поиск по документам придётся делать после расшифровки в памяти, а не в SQL.

## Ограничения и честные допущения

- Данные синтетические, реальные ПДн не используются.
- PII-модуль основан на regex и словаре имён. Это не гарантирует полную анонимизацию:
  по контексту человека всё ещё можно идентифицировать. Для продакшена нужен локальный LLM
  или провайдер с DPA, а также DLP и юридическая оценка.
- Vosk small-ru — лёгкая модель для локальной расшифровки. Она может путать редкие имена
  и термины, не делает диаризацию спикеров. Для пилота лучше Whisper/large или платный STT
  с DPA; аудио при этом всё равно можно оставить локальным.
- Для DeepSeek расшифровка ограничена 24 тыс. символов, а каждый документ — 6 тыс. символов.
  Это защита контекста; длинные встречи нужно резать на части или использовать модель с большим окном.
- RAG для демо — keyword-scoring, не векторная база. Для пилота: Qdrant/Chroma + ACL в metadata.
- Вкладка «Документы» ищет по ключевым словам, а не по смыслу. Для больших баз нужен
  embedding-поиск; ACL при этом всё равно должен применяться до выдачи фрагментов.
- Загруженные `.pdf` разбираются по текстовому слою. Сканы без OCR не индексируются.
- Защита от prompt injection — инструкция в системном промпте и обёртка `<documents>`.
  Это снижает риск, но не является формальной гарантией; нужен отдельный тест-набор атак.
- Аудит и лимиты рассчитаны на один процесс; для продакшена — PostgreSQL/Redis.
- Календарь и часть задач в интерфейсе используют синтетические данные на клиенте, но
  фильтруются по текущей роли. Задачи из протоколов уже сохраняются в SQLite. Для продакшена
  календарь и остальные сущности нужно перевести на `/api/*`.
- DeepSeek — внешний сервис. Перед реальными ПДн нужно проверить актуальные условия обработки,
  регион и правовые основания; маскирование снижает риск, но не заменяет DPA.
- Автовход директора — только для демо. В продакшене нужен реальный вход сотрудников, HTTPS
  и нормальная аутентификация без общего демо-аккаунта.
