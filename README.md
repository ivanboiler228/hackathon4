# Фотопринт · AI-ассистент руководителя

Хакатонный прототип трека 3: защищённый слой для работы AI-ассистента с корпоративными
документами. Интерфейс оставлен в исходном дизайне; добавлены только вход по одному QR
и переключение «директор → сотрудник» в профиле.

## Что работает

- **Один QR-код для входа директора.** Одноразовая ссылка, после сканирования открывается
  приложение под аккаунтом Анны Ковалёвой.
- **Переключение роли в профиле.** Директор открывает аватар → «Просмотр как» → выбирает
  сотрудника. Сессия остаётся директорской, но API начинает работать с правами сотрудника.
  Вернуться обратно можно там же.
- **RBAC на бэкенде.** Роль и `user_id` берутся из подписанной HttpOnly-cookie, а не из
  запроса. Документы фильтруются по ACL до ранжирования.
- **PII-маскирование.** Телефоны, email, УНП, паспорта, IBAN, карты, ФИО и организации
  заменяются тегами `⟦PERSON_1⟧`, `⟦PHONE_1⟧`. Во внешнюю модель уходит только обезличенный текст.
- **Обратная подстановка.** Реальные значения возвращаются на сервере в ответ только текущему
  пользователю. Словарь соответствий живёт в памяти одного запроса.
- **DeepSeek + fallback.** Если задан ключ, ответ строит DeepSeek. Если ключа нет или модель
  недоступна, используется локальный детерминированный ответ по документам — демо не падает.
- **Источники и дата.** Ответ `/api/assistant/ask` содержит документы-основания.
- **Аудит.** Пишутся пользователь, роль, действие, объект, результат, источники и маскированный
  фрагмент запроса. Сырые ПДн в аудит не попадают.
- **Защита от инъекций.** Модель получает инструкцию считать содержимое документов данными,
  не выполнять команды из них. Доступ к документам всё равно проверяется на сервере.
- **Rate limit.** По умолчанию 20 запросов в минуту на пользователя.

> Чат в интерфейсе специально не добавлен — по договорённости UI пока остаётся исходным.
> Безопасный pipeline доступен через API и Swagger `/docs`; UI для чата доработаем отдельно.

## Быстрый запуск

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
# впишите DEEPSEEK_API_KEY в .env, если нужен DeepSeek
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Откройте `http://127.0.0.1:8000/` — без сессии откроется страница входа.

> `SECRET_KEY` в `.env` обязателен для стабильных сессий. `.env` в git не коммитится.
> `DEEPSEEK_API_KEY` не передавайте в чат и не коммитьте.

## QR-код

```powershell
# для ноутбука
python scripts\make_qr.py --base-url http://127.0.0.1:8000

# для телефона: укажите LAN-IP компьютера
python scripts\make_qr.py --base-url http://192.168.1.65:8000
```

Скрипт создаёт:
- `qr/director.png` — единственный публичный QR для входа директора;
- `qr/index.html` — страница с этим QR для показа на стенде.

Код одноразовый: после первого сканирования нужен новый. Старые PNG удаляются при генерации.
Для отладки всех пользователей: `python scripts\make_qr.py --all`.

Для телефона:
1. Запустите сервер с `--host 0.0.0.0`.
2. Разрешите порт 8000 в брандмауэре Windows.
3. Сгенерируйте QR с адресом `http://<LAN-IP>:8000`.
4. Сканируйте QR камерой — откроется приложение под директором.
5. В профиле выберите сотрудника для проверки ограничений.

## DeepSeek

В `.env`:

```dotenv
DEEPSEEK_API_KEY=...
DEEPSEEK_MODEL=deepseek-chat
```

Ключ читается только на сервере. Если ключа нет, в ответе будет `used_llm: false` и
`llm_error: "disabled"`. Перед любым вызовом модели бэкенд маскирует вопрос и документы
и проверяет, что в отправляемом тексте не осталось известных шаблонов ПДн.

## API

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/health` | статус, включена ли LLM |
| GET | `/login` | страница входа по QR |
| GET | `/auth/qr?code=...` | одноразовый вход, ставит HttpOnly cookie |
| POST | `/api/logout` | выход |
| GET | `/api/me` | текущий пользователь, роль и варианты переключения |
| POST | `/api/switch-role` | директор смотрит как сотрудник или возвращается |
| GET | `/api/docs` | документы, разрешённые роли |
| GET | `/api/docs/{id}` | документ с проверкой ACL |
| POST | `/api/assistant/ask` | вопрос по документам, PII-маскирование, LLM/fallback |
| GET | `/api/audit` | аудит: директор видит всё, сотрудник — только своё |

Пример ответа `/api/assistant/ask`:

```json
{
  "answer": "SLA первого ответа — 92% при цели 95%. [D-07]",
  "sources": [{"id": "D-07", "title": "Отчёт по SLA поддержки, октябрь", "date": "2026-11-03", "acl": "all"}],
  "masked_preview": "Вопрос: ... ⟦PERSON_1⟧ ... ⟦PHONE_1⟧ ...",
  "pii_found": {"PERSON": 1, "PHONE": 1},
  "used_llm": false,
  "llm_error": "disabled"
}
```

Пример переключения:

```powershell
curl -X POST http://127.0.0.1:8000/api/switch-role ^
  -H "Content-Type: application/json" ^
  -b cookies.txt -d "{\"user_id\":\"igor\"}"
```

## Демо-сценарий

1. Сканировать единственный QR — открывается аккаунт директора.
2. Открыть профиль (аватар) — показать «Просмотр как» и список сотрудников.
3. Переключиться на Игоря (производство).
4. Через `/docs` или `curl` отправить `POST /api/assistant/ask` с вопросом «Что в D-12?» —
   получить 403 и запись в аудите.
5. Вернуться в профиль и переключиться обратно на директора.
6. Отправить вопрос с телефоном/ФИО — показать в ответе `masked_preview` с `⟦PERSON_1⟧`
   и `⟦PHONE_1⟧`; в аудите сырых ПДн нет.

## Ограничения и честные допущения

- Данные синтетические, реальные ПДн не используются.
- PII-модуль основан на regex и словаре имён. Это не гарантирует полную анонимизацию:
  по контексту человека всё ещё можно идентифицировать. Для продакшена нужен локальный LLM
  или провайдер с DPA, а также DLP и юридическая оценка.
- RAG для демо — keyword-scoring, не векторная база. Для пилота: Qdrant/Chroma + ACL в metadata.
- Аудит и лимиты рассчитаны на один процесс; для продакшена — PostgreSQL/Redis.
- Календарь и задачи в интерфейсе пока используют синтетические данные на клиенте.
  Серверная авторизация защищает API и документы; следующим шагом нужно перевести задачи и
  календарь на `/api/*`.
- DeepSeek — внешний сервис. Перед реальными ПДн нужно проверить актуальные условия обработки,
  регион и правовые основания; маскирование снижает риск, но не заменяет DPA.
- Для телефона на этом стенде используется HTTP по локальной сети — только для синтетических данных.
  В продакшене обязателен HTTPS: и QR-токен, и вопрос пользователя не должны идти открытым текстом.
- QR-код в демо передаётся в query string и может попасть в access-лог сервера. Токен одноразовый
  и короткоживущий; для продакшена нужен обмен кода через POST/редирект без логирования.
